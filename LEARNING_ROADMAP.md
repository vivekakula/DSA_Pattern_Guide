## Senior Software Engineering Interview Practice
This roadmap covers DSA coding practice only. Senior interviews may also assess system design, project ownership, technical leadership, communication, and role-specific expertise. Keep these areas in your weekly plan instead of postponing them until the end.

Each week, add:
- **System design**: practice one design prompt. Clarify requirements, outline the API and data model, draw the main components, then discuss scale, reliability, security, and tradeoffs.
- **Project deep dive**: prepare one example you personally led. Explain the problem, your decisions, alternatives, outcome, and what you would change now.
- **Leadership and behavior**: practice concise examples about disagreement, mentoring, failure, ambiguity, and incident response. Be specific about your role and impact.
- **Mock interview review**: ask for feedback on correctness, communication, prioritization, and how you handled new information, not only whether you reached an answer.

Adapt this plan to the role description and interview format. No general DSA schedule can prepare you for every senior role or company.

### How to Handle Tough Weeks at Work

Some weeks you will only get 3–4 days of study instead of 5. Here is how to handle it without losing progress:

| Situation | What to Do |
|-----------|-----------|
| Missed 1 day | Skip it. Continue from next day's task. Do NOT double up. |
| Missed 2–3 days | Do Sunday review first. Then resume from where you stopped. |
| Missed a full week | Spend first 2 days back doing ONLY the cheatsheet + 1 easy LC per pattern done so far. Then resume. |
| Back-to-back crunch weeks | Drop to maintenance mode: 20 min/day, ONLY the morning review habit. No new learning. |

> **Maintenance mode** (20 min/day during crunch): Write 1 template from memory each morning. Solve 1 easy LeetCode problem. That's it. This keeps retrieval paths open without requiring full sessions.

---

### What 1.5 Hours Per Day Teaches You That 3 Hours Does Not

Counterintuitively, shorter sessions have a hidden advantage: **forced prioritization**.

When you only have 90 minutes, you cannot afford to passively re-read. You are forced to:
- Write templates from memory (active recall — most effective learning technique)
- Solve fewer but better-chosen problems
- Move on even if something feels shaky — and revisit it via spaced repetition

Shorter sessions can make it easier to return to material regularly. Choose a pace you can sustain and review earlier topics as you go.

**Pattern Template**:
```cpp
vector<vector<int>> mergeIntervals(vector<vector<int>>& intervals) {
    if (intervals.empty()) return {};
    
    // Step 1: Sort by start time
    sort(intervals.begin(), intervals.end());
    
    vector<vector<int>> result;
    result.push_back(intervals[0]);
    
    // Step 2: Iterate and merge
    for (int i = 1; i < intervals.size(); i++) {
        if (intervals[i][0] <= result.back()[1]) {
            // Overlapping - merge
            result.back()[1] = max(result.back()[1], intervals[i][1]);
        } else {
            // Not overlapping - add new interval
            result.push_back(intervals[i]);
        }
    }
    
    return result;
}
```

**BFS Template** (Level Order):
```cpp
vector<vector<int>> levelOrder(TreeNode* root) {
    if (!root) return {};
    
    vector<vector<int>> result;
    queue<TreeNode*> q;
    q.push(root);
    
    while (!q.empty()) {
        int level_size = q.size();
        vector<int> current_level;
        
        for (int i = 0; i < level_size; i++) {
            TreeNode* node = q.front();
            q.pop();
            current_level.push_back(node->val);
            
            if (node->left) q.push(node->left);
            if (node->right) q.push(node->right);
        }
        
        result.push_back(current_level);
    }
    
    return result;
}
```

**DFS Template**:
```cpp
int maxDepth(TreeNode* root) {
    if (!root) return 0;
    return 1 + max(maxDepth(root->left), maxDepth(root->right));
}
```

**Min Heap Template** (for K Largest):
```cpp
vector<int> kLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> minHeap;  // Min heap
    
    for (int num : nums) {
        minHeap.push(num);
        if (minHeap.size() > k) {
            minHeap.pop();  // Remove smallest
        }
    }
    
    vector<int> result;
    while (!minHeap.empty()) {
        result.push_back(minHeap.top());
        minHeap.pop();
    }
    
    return result;
}
```

**Backtracking Template**:
```cpp
void backtrack(vector<int>& current, vector<vector<int>>& result, 
               vector<int>& nums, int start) {
    // Base case: found valid solution
    result.push_back(current);
    
    for (int i = start; i < nums.size(); i++) {
        // Choose
        current.push_back(nums[i]);
        
        // Explore
        backtrack(current, result, nums, i + 1);
        
        // Unchoose (backtrack)
        current.pop_back();
    }
}

vector<vector<int>> subsets(vector<int>& nums) {
    vector<vector<int>> result;
    vector<int> current;
    backtrack(current, result, nums, 0);
    return result;
}
```

**1D DP Template** (Fibonacci-style):
```cpp
int climbStairs(int n) {
    if (n <= 2) return n;
    
    vector<int> dp(n + 1);
    dp[1] = 1;
    dp[2] = 2;
    
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i-1] + dp[i-2];
    }
    
    return dp[n];
}
```

**2D DP Template** (Longest Common Subsequence):
```cpp
int longestCommonSubsequence(string text1, string text2) {
    int m = text1.length(), n = text2.length();
    vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
    
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (text1[i-1] == text2[j-1]) {
                dp[i][j] = dp[i-1][j-1] + 1;
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1]);
            }
        }
    }
    
    return dp[m][n];
}
```

**Kahn's Algorithm Template**:
```cpp
vector<int> in_degree(n, 0);
for (auto& pre : prerequisites) {
    adj[pre[1]].push_back(pre[0]);
    in_degree[pre[0]]++;
}
queue<int> q;
for (int i = 0; i < n; i++) if (in_degree[i] == 0) q.push(i);
vector<int> order;
while (!q.empty()) {
    int node = q.front(); q.pop();
    order.push_back(node);
    for (int nb : adj[node]) if (--in_degree[nb] == 0) q.push(nb);
}
// order.size() != n means cycle exists (can't finish all courses)
```

 🎓 Learning Principles

 The 4-Step Learning Process:

**1. Understand** (Why does this work?)
- Don't just memorize - understand the logic
- Draw diagrams, trace through examples
- Ask: "Why is this better than brute force?"

**2. Implement** (Can I code it?)
- Code templates from memory
- Type, don't copy-paste
- Make mistakes and fix them

**3. Practice** (Can I recognize it?)
- Solve variations of the pattern
- Time yourself
- Focus on pattern recognition first, optimization second

**4. Review** (What did I miss?)
- Compare your solution with optimal one
- Note down mistakes
- Understand why you didn't see the pattern

 🎯 Problem-Solving Framework

 Use this for EVERY problem:

**Step 1: Understand (2 min)**
- What's the input/output?
- Any constraints? (size, values, sorted?)
- Edge cases? (empty, single element, duplicates?)

**Step 2: Identify Pattern (3 min)**
- Check cheatsheet keywords
- What data structure fits?
- Is it sorted? Contiguous? Optimization?

**Step 3: Plan (5 min)**
- Choose the pattern
- Write pseudocode outline
- Identify edge cases to handle

**Step 4: Code (15-20 min)**
- Use the template
- Handle edge cases
- Keep it clean and readable

**Step 5: Test (5 min)**
- Test normal cases
- Test edge cases
- Trace through with example

**Step 6: Optimize (5 min)**
- Can you reduce time complexity?
- Can you reduce space complexity?
- Is this the best approach?

**Total: 30-40 minutes per medium problem**

## 🧠 How to Stop Forgetting: The Spaced Repetition System

### Why You Forget (The Science in 1 Minute)

Hermann Ebbinghaus discovered the **Forgetting Curve** in 1885 — it still holds today:

```
Memory retained (%)

100% ─ ✦ (just learned)
 70% ─     ✦ (1 day later — without review)
 50% ─         ✦ (1 week later)
 25% ─              ✦ (1 month later)
  0% ─                    ✦ (forgotten)

BUT with review at the right time:
100% ─ ✦     ✦        ✦              ✦
       learn  +1day   +1week         +1month
       Each review RESETS the forgetting curve higher
```

The solution is not "study more" — it's **review at the right intervals**. This is called **spaced repetition**.

---

### Your Spaced Repetition Schedule (Built into This Roadmap)

For every pattern you learn, review it on this schedule:

| When | What to Do | Time |
|------|-----------|------|
| **Same day** (evening) | Write the template from memory on paper WITHOUT looking | 10 min |
| **Next day** (morning) | Solve 1 easy problem from that pattern cold (no notes) | 20 min |
| **Day 3** | Solve 1 medium problem from that pattern cold | 30 min |
| **Day 7** | Re-read ONLY the "When to Use" and "Keywords" section | 5 min |
| **Day 14** | Solve 1 new problem from that pattern — time yourself | 25 min |
| **Day 28** | Take the Active Recall quiz in `01_pattern_overview.md` | 15 min |

Use this schedule as a reminder system, and adjust it when the workload is too large or a topic needs more practice.

### The 3-Layer Memory System

Think of your DSA knowledge in 3 layers. Each layer needs a different strategy:

#### Layer 1: Pattern Recognition (Fastest to Forget)
**What it is**: Knowing WHICH pattern to use when you see a problem.  
**How to build it**: Do the Active Recall quiz in `01_pattern_overview.md` every Sunday.  
**Rule**: If you can't identify the pattern within 60 seconds, you don't own Layer 1 yet.

#### Layer 2: Template Recall (Medium to Forget)
**What it is**: Being able to write the core template from memory.  
**How to build it**: Every morning, pick 1 random pattern and write its template on paper before opening any file.  
**Rule**: If you need to look at the file, that pattern goes back on your "review list."

#### Layer 3: Problem Solving (Slowest to Forget)
**What it is**: Applying a known template to a new variation.  
**How to build it**: Solving 2–3 LeetCode problems per pattern each week.  
**Rule**: Once you can solve a medium problem in under 20 min, you own Layer 3 for that pattern.

### Your Weekly Review Schedule (Add This to Your Routine)

Every week has a **built-in review day**. Here is exactly what to do on review days:

#### Sunday Review (45 minutes — non-negotiable)

**Part 1 — Pattern Flash Cards (10 min)**  
Open `pattern_cheatsheet.md`. Cover the right column. Read each keyword row and say the pattern out loud. Any you hesitate on → add to this week's review list.

**Part 2 — Template Write-Up (15 min)**  
Pick the 2 patterns you learned this week. Close all files. Write both templates on paper from memory. Check against the file. Circle what you got wrong.

**Part 3 — Cold Problem (20 min)**  
Pick any problem you solved 7+ days ago. Solve it again from scratch with a timer. You should be ~30% faster than the first time. If not, that pattern needs more practice.

### The "I Forgot It All" Recovery Protocol

If you take a break and feel like you've forgotten everything, do not start over. Use this:

**Day 1 of Recovery**: Read ONLY `pattern_cheatsheet.md` — keywords and complexity table. Nothing else. (20 min)

**Day 2**: Take the Active Recall quiz in `01_pattern_overview.md`. Score yourself honestly. (15 min)

**Day 3 onwards**: For each pattern you scored wrong on the quiz, solve 1 easy LeetCode problem from that pattern. Recognition returns faster than you think — muscle memory stays longer than conscious memory.

> **Key insight**: You haven't forgotten the concept. You've forgotten the *retrieval path*. Solving even 1 problem reopens that path instantly. This is called **reactivation** and it's much faster than the original learning.
